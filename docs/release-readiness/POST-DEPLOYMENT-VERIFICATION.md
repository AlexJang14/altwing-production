## Private API coverage

Use the same signed-in backend origin for authorized requests. Repeat applicable reads signed out and as an unlisted account; no read/report/export should expose data cross-origin. Check both impact-v2 and impact-v3 filters without seeding rows merely to populate a version.

- GET `/api/analytics/report?days=7`
- GET `/api/impact/report?range=all`
- GET `/api/impact/export?range=all&kind=ratings` and `kind=feedback`
- GET `/api/impact/assessment-report?range=all&version=impact-v3&source=wingmatch`
- GET `/api/impact/stories?range=all&version=impact-v3`
- GET `/api/impact/assessment-export?range=all&version=impact-v3&kind=responses`, `kind=stories`, and `kind=quotes`
- POST `/api/impact/initialize`: unauthorized requests must be denied before writes. An authorized request is used only for deliberate historical preparation; do not call it repeatedly as a harmless read.

Public POST/OPTIONS session, analytics event, assessment event and feedback ingestion remain available under their existing consent/origin/capability validation. Public GET must never turn an ingestion endpoint into a stored-feedback listing.
